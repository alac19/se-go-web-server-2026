## 一、技术选型

| 类别              | 选型                                   | 版本              | 理由                               |
| ----------------- | -------------------------------------- | ----------------- | ---------------------------------- |
| 编程语言          | Go                                     | 1.25+             | 原生并发，标准库强大，适合网络服务 |
| HTTP/HTTPS 服务器 | `net/http`                             | 标准库            | 无需第三方，性能优秀，支持 HTTP/2  |
| 反向代理          | `httputil.ReverseProxy`                | 标准库            | 成熟稳定，处理边界情况             |
| 配置解析          | `BurntSushi/toml`                      | v1.3              | 轻量、纯 Go、支持反序列化到结构体  |
| 日志              | `log/slog`                             | 标准库 (Go 1.21+) | 结构化日志，支持 JSON 输出，可扩展 |
| TLS               | `crypto/tls`                           | 标准库            | 安全、简单，无外部依赖             |
| 测试              | `testing` 标准库 + `net/http/httptest` | 标准库            | 集成方便，模拟后端                 |

## 二、配置规范

### 4.1 配置文件格式
- 使用 TOML，示例 `config.toml`：
  ```toml
  [http]
  addr = "127.0.0.1"
  port = 8080

  [https]
  addr = "127.0.0.1"
  port = 8443
  cert_file = "cert.pem"
  key_file = "key.pem"

  [heartbeat]
  enabled = true
  path = "/heartbeat"
  interval_seconds = 30
  timeout_seconds = 2

  [[backends]]
  addr = "127.0.0.1"
  port = 9091

  [[backends]]
  addr = "127.0.0.1"
  port = 9092
  ```

### 4.2 配置加载
- 使用 `BurntSushi/toml` 一次性解码到结构体。
- 配置校验：端口范围、地址非空、心跳间隔为正数等。

## 四、代码规范

### 3.1 命名规范
| 类型      | 规则                                           | 示例                         |
| --------- | ---------------------------------------------- | ---------------------------- |
| 包名      | 小写、无下划线                                 | `config`, `lb`               |
| 结构体    | 大驼峰式命名法                                 | `LoadBalancer`               |
| 接口      | 大驼峰式命名法，单方法可加 `-er`               | `HealthChecker`              |
| 函数/方法 | 大驼峰式命名法（导出）或小驼峰式命名法（私有） | `Next()`, `startHeartbeat()` |
| 变量      | 小驼峰式命名法                                 | `backendURL`                 |
| 常量      | 大驼峰式命名法 或全大写                        | `MaxRetries`                 |

### 3.2 注释规范
- 每个导出的符号（结构体、函数、常量）必须有文档注释，以符号名开头。
  ```go
  // LoadBalancer 实现轮询负载均衡，线程安全。
  type LoadBalancer struct { ... }
  
  // Next 返回下一个可用的后端 URL。
  // 如果没有可用后端，返回 nil。
  func (lb *LoadBalancer) Next() *url.URL { ... }
  ```
- 复杂逻辑需要行内注释说明。

### 3.3 错误处理
- 使用 `errors.New` 或 `fmt.Errorf` 创建错误，不 panic（除非初始化失败）。
- 错误消息小写开头，不加标点。
- 示例：
  ```go
  if len(backends) == 0 {
      return nil, fmt.Errorf("no healthy backends")
  }
  ```

## 五、日志规范

- **日志库**：`log/slog`（Go 1.21+）。
- **输出格式**：JSON（便于日志收集），开发时可改为 Text。
- **日志级别**：
  - `DEBUG`：详细调试信息（开发环境）
  - `INFO`：正常请求日志（方法、路径、耗时、后端地址）
  - `WARN`：后端健康检查失败、配置热重载事件
  - `ERROR`：转发错误、监听失败
- **示例日志行**：
  ```json
  {"time":"2026-04-19T10:30:00Z","level":"INFO","msg":"request","method":"GET","path":"/test","duration_ms":5,"backend":"127.0.0.1:9091"}
  ```

## 六、测试规范

- **单元测试**：每个包至少有一个 `_test.go`，使用表驱动测试。
- **示例**：
  ```go
  func TestLoadBalancerRoundRobin(t *testing.T) {
      backends := []*url.URL{{Host: "a"}, {Host: "b"}}
      lb := NewLoadBalancer(backends)
      if got := lb.Next().Host; got != "a" { t.Errorf("got %s, want a", got) }
      if got := lb.Next().Host; got != "b" { t.Errorf("got %s, want b", got) }
  }
  ```
- **集成测试**：使用 `httptest.NewServer` 模拟后端，测试完整转发流程。

## 七、性能与可观测性

- **基准测试**：提供 `BenchmarkLoadBalancerNext` 等，记录每次操作耗时。
- **pprof 支持**：可嵌入 `net/http/pprof` 用于性能分析（生产环境可关闭）。
- **指标暴露**（可选）：通过 `/metrics` 端点暴露 Prometheus 格式的请求计数、延迟分布。

## 八、构建与部署规范

- **版本管理**：使用 `git tag` 标记版本（如 `v1.0.0`）。
- **构建命令**：`CGO_ENABLED=0 go build -ldflags="-s -w" -o proxy ./cmd/proxy`
- **容器化**：多阶段 Dockerfile，最终镜像基于 `scratch` 或 `alpine`。
- **运行**：`./proxy -config ./configs/config.toml`

## 九、版本控制规范

### **9.1 分支策略**
- **main**：生产分支，仅接受来自 `develop` 的 PR。
- **develop**：开发主分支，集成所有功能。
- **feature/***：功能分支，基于 `develop`，完成后通过 PR 合并。
- **hotfix/***：紧急修复分支，基于 `main`，合并到 `main` 和 `develop`。

### **9.2 提交信息规范**
```
<类型>: <简短描述>

<详细描述>（可选）
```
- 类型：`feat`（新功能）、`fix`（修复）、`docs`（文档）、`refactor`（重构）、`test`（测试）、`chore`（构建/工具）。
- 描述清晰，简洁明了。

### **9.3 代码审查清单**
- 代码符合命名规范。
- 无 `clippy` 警告。
- 新增功能有单元测试。
- 文档注释完整。
- 错误处理得当。
