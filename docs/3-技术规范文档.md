## 二、配置规范

### 4.1 配置文件格式
- 使用 TOML，示例 `config.toml`：
  ```toml
  # 监听端口列表
  [[listen]]
  listen_addr = "127.0.0.1"
  listen_port = 8080   # HTTP 端口

  [[listen]]
  listen_addr = "127.0.0.1"
  listen_port = 8443   # HTTPS 端口

  # 后端服务器列表
  [[forward]]
  forward_addr = "127.0.0.1"
  forward_port = 9091

  [[forward]]
  forward_addr = "127.0.0.1"
  forward_port = 9092

  [[forward]]
  forward_addr = "127.0.0.1"
  forward_port = 9093

  # 心跳检测配置
  [heartbeat]
  enabled = true
  path = "/heartbeat"
  interval_seconds = 30
  timeout_seconds = 2

  # 代理转发配置
  [proxy]
  timeout_seconds = 30   # 转发后端请求的超时时间

  # TLS 配置
  [tls]
  cert_file = "cert.pem"
  key_file = "key.pem"

  # 日志配置 
  [log]
  level = "info"
  file_path = "log.txt"
  ```

### 4.2 配置加载
- 使用 `BurntSushi/toml` 一次性解码到结构体。
- 配置校验：端口范围、地址非空、心跳间隔为正数等。

## 四、代码规范

### 3.1 命名规范
| 类型      | 规则                                           | 示例                         |
| --------- | ---------------------------------------------- | ---------------------------- |
| 包名      | 小写、无下划线                                 | `config`, `lb`               |
| 结构体    | 大驼峰式命名法                                 | `LoadBalancer`               |
| 接口      | 大驼峰式命名法，单方法可加 `-er`               | `HealthChecker`              |
| 函数/方法 | 大驼峰式命名法（导出）或小驼峰式命名法（私有） | `Next()`, `startHeartbeat()` |
| 变量      | 大驼峰式命名法（导出）或小驼峰式命名法（私有） | `Listen`, `backendURL`       |
| 常量      | 大驼峰式命名法 或 全大写                       | `MaxRetries`                 |

### 3.2 注释规范
- 每个导出的符号（结构体、函数、常量）必须有文档注释，以符号名开头。
  ```go
  // LoadBalancer 提供轮询算法，线程安全。
  type LoadBalancer struct { ... }
  
  // / 返回下一个可用的后端 URL（轮询）
  // / # 参数
  // / - lb: 创建的 LoadBalancer 实例
  // /
  // / # 返回
  // / - *url.URL: 下一个可用的后端 URL，如果没有后端，返回 nil
  func (lb *LoadBalancer) Next() *url.URL { ... }
  ```
- 复杂逻辑需要行内注释说明。

### 3.3 错误处理
- 使用 `http.Error` 或 `fmt.Errorf` 创建错误，不 panic（除非初始化失败）。
- 错误消息小写开头，不加标点。
- 示例：
  ```go
	if len(config.Listen) == 0 {
		return nil, fmt.Errorf("配置中没有 listen 项")
	}
  ```

## 五、日志规范

- **日志库**：`log/slog`（Go 1.21+）。
- **输出格式**：JSON（便于日志收集），开发时可改为 Text。
- **日志级别**：
  - `DEBUG`：详细调试信息（开发环境）
  - `INFO`：正常请求日志（方法、路径、耗时、后端地址）
  - `WARN`：后端健康检查失败、配置热重载事件
  - `ERROR`：转发错误、监听失败
- **示例日志行**：
  ```json
  {"time":"2026-04-25T23:41:03.6470074+08:00","level":"INFO","msg":"日志系统已初始化","level":"info","file":"log.txt"}
  ```

## 六、测试规范

- **单元测试**：每个包至少有一个 `_test.go`，使用表驱动测试。
- **示例**：
  ```go
  // 测试轮询算法：按顺序循环返回
  func TestLoadBalancerRoundRobin(t *testing.T) {
    backends := testBackends()
    lb := New(backends)

    expected := []string{
      "127.0.0.1:9091",
      "127.0.0.1:9092",
      "127.0.0.1:9093",
      "127.0.0.1:9091", // 第4次回到第一个
      "127.0.0.1:9092",
    }

    for i, want := range expected {
      got := lb.Next()
      if got == nil {
        t.Fatalf("第 %d 次调用 Next() 返回 nil", i)
      }
      if got.Host != want {
        t.Errorf("第 %d 次调用 Next() 返回 Host = %s，期望 %s", i, got.Host, want)
      }
    }
  }
  ```
- **集成测试**：使用 `httptest.NewServer` 模拟后端，测试完整转发流程。

## 八、构建与部署规范

- **版本管理**：使用 `git tag` 标记版本（如 `v1.0.0`）。
- **本地构建命令**（可选）：`CGO_ENABLED=0 go build -ldflags="-s -w" -o proxy ./src/main.go`
- **容器化构建**：
  - 提供多阶段 `Dockerfile`，最终镜像基于 `alpine:latest`，体积约 **16MB**（≤30MB）。
  - 构建镜像：`docker build -t se-go-web-server-2026-proxy .`
- **运行方式**：
  - **使用 Docker Compose（推荐）**：`docker-compose up -d`  
    一键启动反向代理 + 三个模拟后端（`hashicorp/http-echo`），代理监听 `8080`（HTTP）和 `8443`（HTTPS）。
  - **单独运行代理容器**：`docker run -p 8080:8080 -p 8443:8443 se-go-web-server-2026-proxy`（需自行提供后端服务）
- **配置文件与证书**：容器启动时会挂载 `./configs/config.toml`、`./cert.pem`、`./key.pem`，便于动态修改。

## 九、版本控制规范

### **9.1 分支策略**
- **main**：生产分支，仅接受来自 `develop` 的 PR。
- **develop**：开发主分支，集成所有功能。
- **feature/***：功能分支，基于 `develop`，完成后通过 PR 合并。
- **hotfix/***：紧急修复分支，基于 `main`，合并到 `main` 和 `develop`。

### **9.2 提交信息规范**
```
<类型>: <简短描述>

<详细描述>（可选）
```
- 类型：`feat`（新功能）、`fix`（修复）、`docs`（文档）、`refactor`（重构）、`test`（测试）、`chore`（构建/工具）。
- 描述清晰，简洁明了。

### **9.3 代码审查清单**
- 代码符合命名规范。
- 无 `clippy` 警告。
- 新增功能有单元测试。
- 文档注释完整。
- 错误处理得当。
